# 串口通信协议说明（STM32 ⇄ ESP32-C3）

> 版本：**v2.1**（CRC16 + 序号 + ACK + 超时重传 + 去重）
> 适用：STM32F103C8T6（USART2，PA2/PA3）⇄ ESP32-C3 SuperMini（UART1，GPIO4/GPIO5）

---

## 1. 设计目标

| 目标 | 做法 |
|---|---|
| **抗干扰 / 防数据错** | 每帧末尾附 **CRC-16/CCITT-FALSE** 校验，校验失败直接丢帧 |
| **解决首帧丢失** | 序号 + ACK + 超时重传（最多 3 次），配合 C3 开机 3 分钟内 20s 重发、STM32 上电发 `'R'` 请求 |
| **断网容错** | 取数失败发 `$ERR` 帧（可靠传输），STM32 **保留上一次有效数据**，RTC 本地继续走时 |
| **可调试** | 全 ASCII、一行一帧，串口助手直接可读 |
| **实现简单、两端一致** | CRC 与帧拼接在 Arduino / STM32 标准库两侧用同一份逻辑 |

---

## 2. 物理层

| 项目 | 参数 |
|---|---|
| 波特率 | **115200** |
| 数据位 / 停止位 / 校验 | 8 / 1 / 无 |
| 电平 | 3.3V TTL |
| 接线 | ESP32-C3 **GPIO4(TX) → STM32 PA3(RX)**；**GPIO5(RX) ← STM32 PA2(TX)**；**GND 必须共地** |
| 方向 | 数据：C3 → STM32；ACK：STM32 → C3 |

> 只接 TX（GPIO4→PA3）+ GND 也能工作：STM32 收不到？不，数据能到；ACK 回不去时 C3 会重发 3 次，STM32 靠"序号去重"只应用一次。把 PA2→GPIO5 也接上，重传才会在收到 ACK 后停止，效率最高。

---

## 3. 帧格式

```
$<TYPE>,<seq>,<payload...>*<CRC16>\r\n
```

- `$`：帧头
- `TYPE`：`OK` / `FC` / `FD` / `ERR` / `AK`
- `seq`：序号，0~255 循环，用于重传与去重
- `payload`：各类型自己的字段（见下表）
- `*`：CRC 分隔符
- `CRC16`：4 位大写十六进制，覆盖 **从 `$` 到 `*` 之前** 的全部字节
- `\r\n`：帧尾

---

## 4. 消息类型

### ESP32-C3 → STM32

| 帧 | 字段 | 含义 |
|---|---|---|
| `$OK` | `$OK,<seq>,<utc秒>,<天气码>,<温度>*CRC` | 时间 + 当前实况天气 |
| `$FC` | `$FC,<seq>,<今c>,<今高>,<今低>,<明c>,<明高>,<明低>,<后c>,<后高>,<后低>*CRC` | 三天预报（列表页） |
| `$FD` | `$FD,<seq>,<n>,<c0>,<h0>,<l0>,<c1>,<h1>,<l1>,...*CRC` | n 天预报（温度趋势曲线页，n≤15） |
| `$ERR` | `$ERR,<seq>*CRC` | 本次取数失败（不携带数据） |

### STM32 → ESP32-C3

| 帧 | 字段 | 含义 |
|---|---|---|
| `$AK` | `$AK,<seq>*CRC` | 确认收到并已应用该 `seq` 的帧 |

## 5. CRC-16 原理

把数据看成一个大二进制数，用固定生成多项式去除，**余数就是 CRC**。发送方把余数附在帧尾，接收方重新计算并比对。

**本协议参数：CRC-16/CCITT-FALSE**

| 参数 | 值 |
|---|---|
| 多项式 poly | `0x1021`（x¹⁶+x¹²+x⁵+1） |
| 初值 init | `0xFFFF` |
| 输入/输出反射 | 否 |
| 输出异或 | 否 |
| 结果宽度 | 16 位 |

逐位实现（两端完全一致）：

```c
uint16_t crc16_ccitt(const uint8_t *data, uint16_t len) {
    uint16_t crc = 0xFFFF;
    for (uint16_t i = 0; i < len; i++) {
        crc ^= (uint16_t)data[i] << 8;
        for (uint8_t b = 0; b < 8; b++)
            crc = (crc & 0x8000) ? (uint16_t)((crc << 1) ^ 0x1021)
                                 : (uint16_t)(crc << 1);
    }
    return crc;
}
```

### 为什么用 CRC，而不是奇偶校验/校验和？
- 奇偶校验只能查 1 位错；累加和 / 异或和 对"两个字节同时翻转""字节顺序变化"经常漏检。
- CRC 能检出：**全部单比特错、全部双比特错、奇数个比特错、长度 ≤16 的突发错误**，对串口偶发位翻转/毛刺非常有效。
- 代价极小：每帧 2 字节 + O(n) 运算。

> CRC 只防"传输偶然出错"，不防篡改，也不是加密。

## 6. 可靠传输机制（重点）

### 6.1 序号 seq
每发送一帧分配一个 `seq`（0~255 递增）。**同一帧重传时复用同一个 seq**。

### 6.2 ACK
STM32 收到一帧、CRC 校验通过后，回 `$AK,<seq>*CRC`。

### 6.3 超时重传
C3 发一帧后等待 ACK：`ACK_TIMEOUT_MS = 200ms`，最多重发 `FRAME_RETRY = 3` 次；收到对应 seq 的 ACK 才进入下一帧。

### 6.4 去重（防止重复应用）
STM32 记录"最后应用的 seq"。收到 **seq 与上一帧相同** 的帧 → 判定为重传副本：
- **只补发 ACK，不重复写 RTC / 不重复刷新显示**；
- 避免"ACK 丢了→C3 重发→STM32 又应用一遍"导致时间/数据重复处理。

### 6.5 时序（正常 / ACK 丢失）

```
正常:
  C3:  send $OK,seq=0*CRC  ───────────────▶
  STM32: 校验CRC → seq!=last → 应用 → last=0 → $AK,0 ◀────
  C3:  收到 $AK,0 → seq++ → 下一帧 $FC,seq=1 ...

ACK 丢失:
  C3:  send $OK,seq=0*CRC ──▶  STM32 应用并 last=0，回ACK ✘丢
  C3:  200ms 超时 → 重发 $OK,seq=0*CRC ──▶
  STM32: seq==last(0) → 判定重复 → 只回 $AK,0（不再应用）
  C3:  收到ACK → 继续
```

### 6.6 首帧丢失怎么解决
1. **重传**：上电时 STM32 可能还没启动好，ACK 收不到，C3 会重发 3 次；
2. **开机高频重发**：C3 开机后 **前 3 分钟每 20 秒** 主动刷新一次；
3. **STM32 主动请求**：STM32 上电发 `'R'`，C3 收到立即刷新（需接 PA2→GPIO5）。

三者叠加，基本"上电即显示"，不需要手动复位。

### 6.7 断网容错
- WiFi/API 失败 → C3 发 `$ERR,<seq>`（走可靠传输）；
- STM32 收到 `$ERR` **不清空数据**，继续显示上一次有效的天气/温度；
- 时间由 STM32 本地 RTC 继续走（C3 恢复后再校时）；
- C3 下一轮（每 10 分钟 / 收到 `'R'`）自动重连重取。

## 7. STM32 解析流程

```
USART2 中断：逐字节收 → 收到 '\n' 置 RX_FINISH
ESP32C3_Poll()（主循环反复调用）：
  └ 按 '\n' 把缓冲区拆成多行（一帧可含 $OK/$FC/$FD 多行）
     └ 对每行 ProcessLine():
        1) 找 '*'，解析 4 位 CRC16
        2) 重算 CRC，不一致 → s_crc_err++，丢弃该行
        3) 解析 seq
        4) seq == 上次已应用 seq → 只回 ACK，返回
        5) 按 $OK/$FC/$FD/$ERR 分发解析并更新状态
        6) 记录 last_seq，回 ACK
```

关键状态：`s_ok_cnt / s_fc_cnt / s_crc_ok / s_crc_err / s_last_seq`。

## 10. 参数与调试

| 宏/参数 | 位置 | 默认 | 说明 |
|---|---|---|---|
| `ACK_TIMEOUT_MS` | ESP32 固件 | 200ms | 等 ACK 超时 |
| `FRAME_RETRY` | ESP32 固件 | 3 | 单帧最大发送次数 |
| `UPDATE_INTERVAL_MS` | ESP32 固件 | 10min | 正常刷新周期 |
| 串口波特率 | 两端 | 115200 | 必须一致 |

**排查：**
- STM32 显示 `No data`：看 C3 串口是否打印 `重传 seq=...`（说明 ACK 没回去，检查 PA2→GPIO5 / 共地）；
- 数据偶发不更新：看 `s_crc_err` 是否增长（线太长/干扰/共地不良）；
- 完全没数据：先确认 TX→PA3、GND。

---

## 11. 兼容性
本协议与旧版（无 CRC / 无 seq）**不兼容**，升级时 **ESP32-C3 与 STM32 必须同时烧录新固件**。
